## 二、提交 `de00d84` — R6 收口

### 2.1 R6-1：`static_assert` 下界修正（核心）

**缺陷确认**（与我上轮 §5.1 一致）：

```cpp
// 修正前(R5-7)
static_assert(kTruncBufSize >= 60u*1024u - 27u - 64u - kMarkerReserve + (28 + 10 + 7), ...);
//                            = 61440 − 27 − 64 − 48 + 45 = 61346  ← 多减 tag 上限 64

// 修正后(R6-1)
static_assert(kTruncBufSize >=
                  kHardUserTotal - kUserHdrSize - kMarkerReserve +
                  (sizeof(kMarkerHead) - 1 + kMaxU32Digits + sizeof(kMarkerTail) - 1), ...);
//              = 61440 − 27 − 48 + 45 = 61410  ✓
```

**独立验证**：

| 验证项 | 结果 |
|---|---|
| 算术 | `61440 − 27 − 48 + 45 = 61410` ✅ |
| 单调性论证 | `budget = cap − (kUserHdrSize + tag_len)` 随 `tag_len` **单调递减** → 缓冲最坏取 `tag_len = 0`（空 tag 可达：`tag_len_bounded`/`logx_write:425` 均只拒 NULL）✅ |
| 无符号下溢 | 全部中间量非负（61413 → 61365 → +45），无下溢 ✅ |
| 类型安全 | `kHardUserTotal` 由 `uint64_t` 改 `uint32_t`：值 61440 无溢出；函数内与 `uint64_t cap` 比较/赋值经整型提升，语义不变 ✅ |
| **穷举复核** | **27,301,560 组**（tag 0..64 × max_total 0..70000+ × payload 至 `UINT32_MAX`）→ 真实最坏 **61410**，最坏组合 `max_total=61458, tag_len=0, payload=2e9`（10 位 dropped），`assert 下界 == 真实最坏`，**余量 30B** ✅ |

**结论：修正正确，且断言下界与真实最坏严格相等（紧）** —— 既不过松（失去防护）也不过紧（误报）。这是理想的安全断言形态。

## 三、本次新发现问题

### 3.1 P3 — 常量上提未覆盖权威定义处 `format_record`

R6-1 将 `kUserHdrSize`(27)/`kHardUserTotal`(61440) 上提以"消除魔法数重复"，但**`format_record` 这一权威定义处仍使用自己的字面量**：

```cpp
// core/src/format.cpp:110-111 (format_record,本次未改)
const uint32_t hdr_size = 8 + 4 + 8 + 1 + 2 + 4;   // 27B  ← 与 kUserHdrSize 独立
const uint64_t user_total = static_cast<uint64_t>(hdr_size) + tag_len + payload_len;
if (user_total > 60u * 1024u) return false;         // ← 与 kHardUserTotal 独立
```

**影响**：`static_assert` 的**前提是 `format_record` 的实际门槛**，但该前提仍由两处**互相独立的字面量**表达。若未来 `format_record` 的头部布局或 60KB 上限变更（例如头部增至 28B），`kUserHdrSize` 不会同步——断言将基于过期常量成立，而求解器（亦用 `kUserHdrSize`）与 `format_record` 的真实行为脱钩，`落环总长 ≤ max_total` 不变量可能被破坏。

**当前无实际缺陷**（值一致，61440 ≥ 61410 容差充足），属**潜在漂移风险**。提交声称"消除魔法数重复"仅覆盖求解器内与断言之间，**未触及权威定义处**。

**建议**：让 `format_record` 改用 `kUserHdrSize`/`kHardUserTotal`，使不变量在编译期与权威定义绑定。

### 3.2 P3 — CHANGELOG 旧 R5-7 条目保留已证伪数值

`CHANGELOG.md` 的 R5-7 条目（约 1300-1307 行）仍以**断言口吻**陈述 R6 已证伪的结论：

```
### R5-7 (观察项) marker 常量化 + static_assert 固化安全前提
`trunc_buf` 缩至 60KB 后余量仅 33B ...
`kMarkerReserve`(45 ≤ 48)与 `kTruncBufSize`(最坏 msg 61346 ≤ 61440)不变量;
注释"绰绰有余"改为精确表述(最坏写入 61407B @ max_total=61458/tag=0,余量 33B, ...)
```

其中"**最坏 msg 61346**"与"**61407B/33B**"均已被 R6 自身判定为错误/不精确（真实为 61410/30B）。R6 修正了**代码与代码注释**并新增了**取代性章节**，但**未在该历史条目内加注**，导致 CHANGELOG 中"最坏 msg 61346"与"R5-7 误减 64，真实最坏 61410"两句**并存且互相矛盾**。

**影响**：CHANGELOG 兼具审计轨迹作用，检索 `61346` 会命中一处已证伪的"不变量"陈述。属文档一致性瑕疵，无代码风险。

**建议**：在该行加一句内联取代注（如"→ 见 R6-1：本值有误，真实最坏 61410"），或保持历史条目原样但在其上标注状态。
